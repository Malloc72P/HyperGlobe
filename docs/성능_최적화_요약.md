## 🔧 적용한 3가지 핵심 최적화

### 1. 드로우콜 병합 최적화 ⭐⭐⭐⭐⭐

**문제 상황:**
- 각 폴리곤(링)마다 개별 메쉬와 라인 생성
- world-high: 1,435개 링 → 최소 2,870개 드로우콜
- 실제 측정: 4,320개 드로우콜
- 권장치(~500)의 9배 초과로 GPU 병목 발생

**해결 방법:**
RegionFeature 컴포넌트 내부에서 모든 링을 하나의 메쉬로 병합

```tsx
// RegionFeature.tsx - 최적화된 구현
const regionFeatureGeometry = useMemo(() => {
  if (!meshSource) return;
  
  // 1. 모든 폴리곤의 지오메트리를 하나로 병합
  const geometry = mergeGeometries(meshSource);
  
  // 2. 외곽선도 하나의 lineSegments로 병합
  const points: number[] = [];
  for (const pointArray of feature.borderLines.pointArrays) {
    points.push(...pointArray);
  }
  const borderlineGeometry = new THREE.BufferGeometry();
  borderlineGeometry.setAttribute(
    'position', 
    new THREE.Float32BufferAttribute(points, 3)
  );
  
  return { geometry, borderlineGeometry };
}, [meshSource, feature]);

return (
  <group>
    {/* 국가당 1개 mesh = 256개 드로우콜 */}
    <mesh geometry={regionFeatureGeometry.geometry}>
      <meshStandardMaterial {...props} />
    </mesh>
    <lineSegments geometry={regionFeatureGeometry.borderlineGeometry}>
      <lineBasicMaterial {...props} />
    </lineSegments>
  </group>
);
```

**개선 효과:**
- 드로우콜: 4,320 → 512 (88% 감소)
- 지오메트리: 2,892 → 548 (81% 감소)
- FPS: 24 → 58-60 (+142% 향상)
- 국가별 독립적인 제어 유지 (hover, 색상 변경 가능)

### 2. HGM 포맷 - 빌드 타임 전처리 ⭐⭐⭐⭐⭐

**문제 상황:**
- 브라우저에서 1,435개 폴리곤에 대해 Delaunay 삼각분할 수행
- 초기 로딩: 3-7초 (UI 블로킹 발생)
- CPU 집약적 연산으로 저사양 기기에서 더 심각

**해결 방법:**
빌드 타임에 삼각분할을 미리 수행하고 전처리된 데이터를 HGM 파일로 저장

**HGM 파일 구조:**
```typescript
interface HGMFile {
  version: string;
  features: HGMFeature[];
}

interface HGMFeature {
  id: string;
  properties: Record<string, any>;
  
  // 전처리된 삼각분할 결과
  geometries: GeometrySource[];  // vertices + indices
  
  // 외곽선 좌표
  borderLines: BorderlineSource;
  
  // 공간 인덱싱용
  bbox: BoundingBox;
}
```

**CLI 도구:**
```bash
# GeoJSON → HGM 변환
hyperglobe -i ./world-high.geo.json -o ./world-high.hgm
```

**브라우저에서 사용:**
```typescript
// 전처리된 데이터를 그대로 사용
const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new BufferAttribute(geometrySource.vertices, 3));
geometry.setIndex(new BufferAttribute(geometrySource.indices, 1));
geometry.computeVertexNormals(); // GPU에서 빠르게 계산 (~10ms)
```

**TypedArray 최적화 (v2):**
- JSON 숫자 배열 → Base64 인코딩된 TypedArray
- Float32Array: 숫자당 정확히 4바이트
- Uint32Array: 인덱스당 정확히 4바이트
- gzip 압축과 결합하여 최적의 크기 달성

**개선 효과:**
- 초기 로딩: 3-7초 → < 0.5초 (약 10배 개선)
- 파일 크기: 1.16MB → 378KB (67% 감소, TypedArray 적용 후)
- 브라우저 CPU 부담 제거
- 모든 기기에서 일관된 빠른 로딩

### 3. Globe 벡터 히트 테스트 ⭐⭐⭐⭐⭐

**문제 상황:**
- RegionFeature 병합 후 레이캐스트 성능 악화
- 병합 전: 1,435개 × 350 삼각형 = ~3,500개 검사
- 병합 후: 256개 × 1,979 삼각형 = ~19,790개 검사 (5.6배 증가)
- 매 프레임 포인터 이벤트 시 심각한 블로킹

**해결 방법:**
포인터 이벤트를 RegionFeature가 아닌 Globe 컴포넌트에 배치하고, 3D 레이캐스트 대신 2D 공간 검색 활용

**핵심 아이디어:**
1. Globe의 구체 표면에서 교차점 획득 (단순한 구체 1개만 검사)
2. 3D 벡터 → 경위도 변환 (역변환)
3. R-tree로 후보 지역 빠르게 필터링
4. Point-in-Polygon으로 정확한 지역 식별

**구현:**
```tsx
// Globe.tsx
export function Globe({ ... }: GlobeProps) {
  const rTree = useMainStore((s) => s.tree);
  const setHoveredRegion = useMainStore((s) => s.setHoveredRegion);

  const onPointerMove = useThrottle({
    fn: (e) => {
      const { point } = e;  // R3F가 제공하는 구체 표면 교차점

      const foundRegion = findRegionByVector({
        rTree,
        rotation: UiConstant.globe.rotation,
        vector: point,
      });

      setHoveredRegion(foundRegion);
    },
    delay: 50,  // 50ms throttle
  });

  return (
    <mesh position={position} onPointerMove={onPointerMove}>
      <sphereGeometry args={[1, segments[0], segments[1]]} />
      <meshStandardMaterial {...props} />
    </mesh>
  );
}
```

**findRegionByVector 알고리즘:**
```typescript
export function findRegionByVector({ rotation, vector, rTree }: Options) {
  // 1. 회전 역행렬로 로컬 좌표로 변환
  const inverseMatrix = new Matrix4();
  inverseMatrix.makeRotationFromEuler(new Euler(...rotation));
  inverseMatrix.invert();
  const localPoint = new Vector3(vector.x, vector.y, vector.z)
    .applyMatrix4(inverseMatrix);

  // 2. 3D 좌표 → 경위도 역변환
  const coordinate = CoordinateConverter.invert([
    localPoint.x, 
    localPoint.y, 
    localPoint.z
  ]);

  // 3. R-tree로 후보 지역 필터링 (O(log n))
  const candidates = rTree.search({
    minX: coordinate[0], minY: coordinate[1],
    maxX: coordinate[0], maxY: coordinate[1],
  }).sort((a, b) => a.bboxSize - b.bboxSize);

  // 4. Point-in-Polygon 정밀 검사 (Ray Casting)
  for (const region of candidates) {
    for (const polygon of region.polygons) {
      if (isPointInPolygon(coordinate, polygon)) {
        return region;
      }
    }
  }
  
  return null;
}
```

**Point-in-Polygon (Ray Casting):**
```typescript
export function isPointInPolygon(
  point: [number, number], 
  polygon: Coordinate[]
): boolean {
  const [x, y] = point;
  let inside = false;

  for (let i = 0, j = polygon.length - 1; i < polygon.length; j = i++) {
    const xi = polygon[i]![0], yi = polygon[i]![1];
    const xj = polygon[j]![0], yj = polygon[j]![1];

    const intersect = 
      yi > y !== yj > y && 
      x < ((xj - xi) * (y - yi)) / (yj - yi) + xi;

    if (intersect) inside = !inside;
  }

  return inside;
}
```

**성능 비교:**

| 방식 | 레이캐스트 대상 | 삼각형 검사 | 추가 연산 | 총 시간 |
|------|---------------|------------|----------|---------|
| RegionFeature 병합 | 256개 복잡한 geometry | ~19,790개 | - | ~10ms |
| **Globe 벡터** | **1개 단순 구체** | **~100개** | **벡터변환 + R-tree + PiP** | **< 1ms** |

**개선 효과:**
- 레이캐스트 비용: 99.9% 감소
- 호버 반응 속도: < 1ms
- 60 FPS 안정 유지
- 관심사 분리: Globe(상호작용) / RegionFeature(렌더링)

## 🏗️ 아키텍처 개선

### Zustand Store를 통한 중앙 집중식 상태 관리

```typescript
// main-store.ts
export interface MainStore {
  // R-tree 공간 인덱스
  tree: RBush<RegionModel>;
  
  // 호버된 지역
  hoveredRegion: RegionModel | null;
  
  // 지역 등록/해제
  insertRegionModel: (region: RegionModel) => void;
  removeRegionModel: (region: RegionModel) => void;
  
  // 호버 상태 설정
  setHoveredRegion: (region: RegionModel | null) => void;
}
```

**장점:**
- 단일 진입점에서 모든 호버 처리
- 여러 컴포넌트에서 `hoveredRegion` 구독 가능
- 새로운 지역 추가/제거 용이
- 다른 인터랙션(클릭, 드래그 등) 동일 패턴 적용 가능

## 🎯 핵심 교훈

### 성공한 최적화 전략

1. **빌드 타임 전처리 (HGM)**
   - 브라우저 부담을 빌드 시간으로 이동
   - 사용자 경험 극적 개선

2. **드로우콜 병합**
   - GPU 오버헤드 최소화
   - 동적 기능 보존 (국가별 제어 가능)

3. **차원 축소 (3D → 2D)**
   - 복잡한 3D 레이캐스트 회피
   - 2D 공간 검색 + Point-in-Polygon 활용

4. **관심사 분리**
   - Globe: 상호작용 담당
   - RegionFeature: 렌더링 담당
   - 명확한 책임 분리로 유지보수성 향상

### 핵심 원칙

1. **측정 우선**: 추측이 아닌 프로파일링 기반 최적화
2. **병목 집중**: 가장 큰 문제부터 해결
3. **트레이드오프 고려**: 성능 vs 기능 균형
4. **단순함 추구**: 복잡한 해결책보다 간결한 설계
